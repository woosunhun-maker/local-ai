# secure-chat 작업 규칙

검증되지 않은 기능을 완료됐다고 말하지 않는다. 추측하지 말고, 실패하면 fail-closed로 둔다.

## 보안 경계

- 개인정보·음성·승인 데이터는 Telegram 같은 중앙 채팅을 거치지 않는다.
- Telegram에서 Codex 실행 요청을 받지 않는다. `/codex inspect|draft`는 큐에 넣지 않는다.
- 결제·주문 확정·메일 변경·삭제·원시 브라우저 기능은 기본 차단한다.
- 웹 작업은 사용자가 명시적으로 공유한 Chrome 탭만 대상으로 한다.
- 개인정보 보호형 외부 AI 문의는 집계 숫자만 쓰고 iPhone 승인이 필요하다.
- 불확실한 네트워크 결과는 자동 재시도하지 않는다.
- 보안 경계를 편의를 위해 완화하지 않는다.

## Codex

- Codex는 제한된 코드 스냅샷만 받는다. shell/파일/브라우저/컴퓨터 제어 도구를 주지 않는다.
- 초안은 격리 복사본에서만 검증하고 원본에 자동 적용하지 않는다.

## 비밀값

- 비밀값을 argv, 환경변수, 로그, 설정 파일, 커밋, 채팅에 남기지 않는다.
- Telegram 토큰·API 키·QR 페어링 원문·서명 키는 로그/커밋/채팅에 넣지 않는다.

## 검증

- 서버 변경 후 `npm test`를 실행한다.
- iOS 변경 시 XCTest를 실행하고, 실기기 문제는 기능 부족으로 단정하지 말고 서명·프로비저닝·기기 신뢰부터 확인한다.
