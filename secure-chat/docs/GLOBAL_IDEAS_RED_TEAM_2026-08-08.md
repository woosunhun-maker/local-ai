## 1. 최종 판정

**CONDITIONAL PASS — 아이디어 방향은 타당하지만, 현재 문서만으로 TOP 3 구현 우선순위를 확정하면 안 된다.**

좋은 점은 명확하다.

- 모델 자연어와 실제 실행을 분리한다.
- Telegram과 민감 승인 앱의 권한을 분리한다.
- 가게 시스템이 사람을 범인으로 판정하지 않고 증거 충돌만 제시하도록 제한한다.
- 정상은 숨기고 예외만 올리려 한다.
- 수치를 효과 보장이 아닌 가설로 취급하려는 문구가 있다.

그러나 현재 상태에는 네 가지 중대한 결함이 남아 있다.

1. **운영 기반 TOP 3와 실제 시간 절약 TOP 3가 섞여 있다.** Secure Action Inbox와 Memory Review는 기반 기능이지 아직 시간 절약 기능으로 검증되지 않았다.
2. **86.0/81.6/79.2의 소수점 점수는 재현 가능한 원점수가 없어 과도한 정밀도다.** 가중치만 있고 후보별 항목 점수·평가자·증거 수준이 없다.
3. **가게 CCTV를 기존 안전 목적에서 직원·거래 감사 목적으로 재사용하는 법적 근거와 고지·보유·접근 절차가 빠져 있다.** 얼굴 인식을 하지 않는 것만으로 적법해지지 않는다.
4. **예외만 보여주는 기능은 critical recall이 검증되기 전에 정상 피드를 숨기면 중요한 사건을 누락할 수 있다.** 먼저 그림자 모드에서 기존 검토와 병행해야 한다.

## 2. 출시 차단 수준 발견 사항

### [P0] 가게 CCTV 목적 변경·직원 감시·고객 사생활에 대한 법적 게이트가 없다

관련 원문: 후보 1, 후보 9, Evidence Twin Auditor, 실행 2~3단계.

문서는 얼굴 인식·고의 판단을 금지하지만 다음을 다루지 않는다.

- 기존 CCTV 설치 목적이 시설안전/범죄예방일 때, 이를 직원 지급·업무행동·거래 감사에 상시 사용하는 것이 당초 목적과 합리적으로 관련되는지
- 직원과 고객에게 AI 분석, 생성되는 파생 사건 데이터, 접근자, 보유기간, 이의제기 절차를 어떻게 고지할지
- 공개 장소, 직원 작업구역, 고객이 사용하는 방/ROOM 각각의 촬영 법적 성격과 사생활 기대가 어떻게 다른지
- 직원의 행동·출입·지급 내역을 이름과 연결한 파생 데이터의 수집·이용 근거
- 영상이나 파생 사건을 징계·급여·계약 종료에 사용하는 경우 인간 재검토와 반론권
- 근로자 감시설비에 해당할 때 노사협의회 협의 의무 적용 여부

한국 개인정보 보호법 제25조는 공개된 장소의 고정형 영상정보처리기기 설치·운영을 제한하고, 설치 목적과 다른 방향/목적의 임의 조작 및 녹음 기능 사용을 금지하며 안전조치를 요구한다. 제15조·제18조는 개인정보 수집·이용의 법적 근거와 목적 외 이용 제한을 규정한다. 근로자참여법 제20조는 사업장 내 근로자 감시설비 설치를 노사협의회 협의사항으로 둔다.

- [개인정보 보호법 제25조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1027191403)
- [개인정보 보호법 제15조·제18조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029334879)
- [개인정보보호위원회 민간분야 CCTV 가이드라인 안내](https://m.pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=G010030030&nttId=9870)
- [근로자참여법 제20조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1017145541)

**필수 조치**

1. 법률 검토가 끝나기 전에는 실제 영상 수집·분석·직원별 프로파일 생성을 금지한다.
2. 기존 CCTV 운영관리방침, 안내판, 설치 목적, 촬영구역, 저장기간, 접근권한, 반출 기록을 먼저 감사한다.
3. MVP는 합성 데이터 또는 식별정보를 가린 과거 표본으로만 검증한다.
4. 사건 ID에는 직원 실명·얼굴 특징을 기본 저장하지 않는다. 별도 권한이 있는 매핑 테이블로 분리한다.
5. 분석 결과를 급여·징계·해고·형사 의심의 단독 근거로 사용하는 것을 정책상 금지한다.
6. 적용 대상 사업장에 노사협의회 협의가 필요한지 노무 검토를 받는다.

**출시 게이트:** LEGAL_REVIEWED, CCTV_POLICY_UPDATED, NOTICE_VERIFIED, ACCESS_LOG_ENABLED, RETENTION_SET, EMPLOYEE_PROCESS_DEFINED가 모두 확인되기 전 실제 영상 MVP 금지.

### [P0] CCTV 음성 녹음은 향후 기능 후보에서도 명시적으로 제외해야 한다

사용자의 이전 요구에는 카메라 음성 녹음 희망이 있었다. 현재 아이디어 문서는 이를 언급하지 않아 이후 기능으로 다시 들어올 위험이 있다.

개인정보 보호법 제25조 제5항은 고정형 영상정보처리기기의 녹음기능 사용을 금지한다. 또한 제3자가 공개되지 않은 타인 간 대화를 기계적으로 녹음·청취하는 행위는 통신비밀보호법 위험이 크다.

- [개인정보 보호법 제25조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1027191403)
- [공개되지 않은 타인 간 대화 녹음 판례](https://www.law.go.kr/LSW/precInfoP.do?precSeq=238175)

**필수 조치:** 당장 하지 않을 것에 “CCTV/별도 마이크로 고객·직원의 대화를 녹음·전사하는 일”을 추가한다. 법률 자문 전에는 테스트도 실제 사람의 대화로 하지 않는다.

### [P0] Exception-Only Briefing은 검증 전에 중요한 사건을 숨길 수 있다

관련 원문: 결론 TOP 2, Attention Governor, 실행 4단계.

“정상은 숨긴다”는 설계는 분류기가 정상을 정확하게 인식한다는 전제가 필요하다. 현재는 가게 표준 원장, 시간 동기화, critical event 정의, 누락 표본 자체가 없다. 이 상태에서 예외만 노출하면 사용자 시간을 줄이는 대신 중요한 누락을 보이지 않게 만들 수 있다.

**필수 조치**

- 최초 14일은 기존 전체 기록과 Exception Briefing을 나란히 보여주는 shadow mode로 운용한다.
- critical 사건은 false negative가 한 건이라도 발생하면 자동 요약/숨김 기능을 중단한다.
- UNKNOWN은 정상으로 접지 말고 별도 검토 큐로 보낸다.
- 시스템 장애·데이터 미수신·카메라 시간 불일치 자체를 최상위 예외로 취급한다.
- “알림 후 행동률” 대신 critical recall, false negative count, 누락 발견 지연을 1차 지표로 둔다.

## 3. 높은 우선순위 발견 사항

### [P1] TOP 3의 이름과 평가 목적이 불일치한다

문서에는 세 종류의 TOP 3가 동시에 존재한다.

1. 운영 기능: Secure Action Inbox, Exception-Only Briefing, Memory Review
2. 연구 구조: Capability Forge, Evidence Twin Auditor, Attention Governor
3. 시간 절약 근거가 강한 후보: 이메일·문서 백오피스, 반복적 결정형 Home Assistant 작업, 예외 대조

독자는 무엇이 “최종 3개”인지 혼동할 수 있다. 특히 이메일 자동화는 문서 스스로 공개 시간 절약 근거가 가장 강하다고 평가하지만 최종 TOP 3에서는 빠진다. 반대로 Memory Review는 사용자에게 지속적인 검토 업무를 추가할 수 있는데 3위다.

**권장 수정**

- 필수 운영 기반 TOP 3와 실제 시간 절약 실험 TOP 3를 별도로 표기한다.
- 운영 기반은 순위를 매기지 말고 출시 의존관계로 표시한다.
- 시간 절약 실험 후보는 아래처럼 다시 구성한다.
  1. 읽기 전용 이메일/문서 분류·초안
  2. 표준 Evidence Ledger의 자동 합계·누락 필드 검사
  3. 결정적 Home Assistant 반복 명령/상태 예외
- Memory Review는 시간 절약 상위 기능이 아니라 개인정보·연속성 기반으로 분류한다.

### [P1] 86.0/81.6/79.2는 검증되지 않은 정밀도다

가중치 합계는 공개돼 있지만 후보별 원점수, 점수 부여자, 증거 강도, 불확실성 구간이 없다. 소수점 한 자리 점수는 측정값처럼 보이지만 실제로는 주관적 판단이다.

**권장 수정**

- 점수를 A(즉시 검증) / B(기반 선행) / C(연구) 등급으로 바꾸거나 정수 범위로 표시한다.
- 점수를 유지하려면 후보별 8개 원점수와 산식, 평가일, 평가자, 근거 링크를 부록에 넣는다.
- 7~14일 실험 뒤 순절약시간, 중단 횟수, 오탐 검토시간, 유지보수시간으로 재평가한다.

### [P1] “외부 검증 사실”이 독립 검증처럼 읽힌다

OpenAI 이용 통계는 OpenAI가 발표한 자사 제품 데이터다. Microsoft와 GitHub 생산성 연구도 해당 제품 제공자와 연관된 연구다. 수치 자체는 출처 페이지와 일치하지만 “외부 검증”은 독립 제3자 재현을 뜻하는 것처럼 읽힐 수 있다.

확인된 수치:

- OpenAI 페이지는 150만 대화 표본, 당시 7억 주간 활성 이용자, 49/40/11 분류, 약 70% 비업무 사용을 직접 기재한다: [OpenAI 원문](https://openai.com/index/how-people-are-using-chatgpt/)
- OpenAI Signals는 2025-10-15~2026-05-01 가입자 중 0.1% 표본에서 가입 6개월 뒤 메시지 50% 증가와 사용 작업 종류 2배를 보고한다. 생존자·활성 사용자 선택 효과에 주의해야 한다: [Signals 방법 범위](https://openai.com/index/how-chatgpt-adoption-has-expanded/)
- Microsoft 연구는 도구 실제 이용자의 이메일 시간 3시간/25% 감소와 ITT 1.4시간을 구분한다: [Microsoft 원문](https://www.microsoft.com/en-us/research/publication/shifting-work-patterns-with-generative-ai/)
- 개발자 실험의 26.08%는 세 실험 4,867명을 합친 값이며 표준오차가 10.3%다: [Microsoft 원문](https://www.microsoft.com/en-us/research/publication/the-effects-of-generative-ai-on-high-skilled-work-evidence-from-three-field-experiments-with-software-developers/)

**권장 수정:** 외부 검증 사실을 출처 원문 확인으로 바꾸고 독립 연구, 공급자 연구, 자기보고, 커뮤니티 사례, 설계 유추를 별도 라벨로 나눈다.

### [P1] OpenAI Signals를 “신뢰가 쌓여 용도가 늘어난다”로 해석한 것은 인과 과장이다

Signals가 보여주는 것은 남아 있는 이용자가 시간이 지나며 더 많이, 더 다양한 기능을 사용했다는 관찰이다. 신뢰가 원인이라고 측정하지 않았다. 제품 개선, 선택 편향, 숙련, 사용 필요 증가도 설명 가능하다.

**권장 문구:** “장기 이용자 집단에서 사용 깊이와 범위가 증가했다. 원인이 신뢰 축적인지는 이 자료만으로 확인할 수 없다.”

### [P1] Home Assistant 200만은 현재치가 아니라 2025년 발표 시점의 역사적 수치다

“현재 대규모로 실제 운영”이라는 방향은 타당하지만 200만 활성 설치는 2025년 5월 발표값이다. 공개 analytics는 참여 동의 설치에 기반하므로 현재 전체 설치 수를 직접 나타내지 않는다.

**권장 문구:** “Home Assistant는 2025년 5월 200만 활성 설치를 넘었다고 발표했다. 2026-08-08 현재 총 설치 수로 해석하지 않는다.”

### [P1] GitHub 별 수 스냅샷은 핵심 의사결정에 필요 없고 재현성도 낮다

문서는 별 수가 품질 증거가 아니라고 경고했지만, 정확한 숫자를 길게 제시하면 독자가 순위 근거로 오해할 수 있다. API 조회 시각·API URL·응답 보존본도 없다. 숫자는 매 순간 바뀐다.

**권장 수정**

- 본문에서 삭제하고 필요하면 생태계 성숙도 보조지표 부록으로 이동한다.
- 유지한다면 UTC 조회 시각, GitHub API endpoint, 원 응답 해시를 기록하고 자동 만료일을 둔다.
- 프로젝트 선택은 최근 릴리스, 보안정책, issue 응답성, 데이터 이동, 라이선스, 롤백 가능성으로 평가한다.

### [P1] 공개 구현 존재가 해당 효과의 근거로 과도하게 확장된다

다음 연결은 “비슷한 구성요소가 존재한다”는 증거이지 목표 효과를 검증하지 않는다.

- Frigate 객체 감지/HA 연동 → 병 수·직원 지급·테이블 거래 감사 가능성
- Actual Budget local-first 회계 → 부정 지급/재고 이상 탐지 가능성
- Uptime Kuma/OpenHands → Flight Recorder가 MTTR을 줄인다는 효과
- NanoClaw 컨테이너 → Telegram과 iPhone 권한 handoff의 안전성
- n8n 생태계 → 이 사용자 환경에서 이메일 시간이 줄어드는 효과

**권장 수정:** 표의 공개 구현·근거를 재사용 가능한 구성요소와 효과 근거 두 열로 분리한다. 효과 근거가 없으면 미검증으로 표시한다.

### [P1] 영상 AI 전에 장부 표준화가 필요하다는 결론은 맞지만 OCR도 너무 이르다

현재 장부는 금액·기호·수정 규칙·작성자·마감 책임이 불명확하다. OCR을 붙이면 불명확한 원장을 더 빠르게 디지털화할 뿐이다. 사람이 OCR을 확인하는 시간까지 추가될 수 있다.

**권장 순서**

1. 새 A4 장부를 7일간 수기로 운영한다.
2. 필수 필드 누락률과 수정 사유 기록률을 측정한다.
3. 장부 합계와 실제 계좌/영수증을 사람이 표본 대조한다.
4. 동일 양식이 안정된 뒤 OCR을 그림자 도입한다.
5. OCR 필드 정확도 99% 미만인 금액·수량은 자동 반영하지 않는다.

## 4. 중간 우선순위 발견 사항

### [P2] Secure Action Inbox는 승인 시간을 줄이지 않고 늘릴 수도 있다

iPhone으로 승인 위치가 옮겨지는 것은 Mac 화면 불편을 줄이지만, 승인 카드가 길거나 자주 뜨면 전체 판단시간은 증가한다. Face ID 성공은 내용 이해 증거가 아니다라는 문서의 경고는 적절하다.

**필수 측정:** 승인 1건당 화면 수, 읽기 시간, 거부율, 만료율, 승인 후 되돌림, 같은 목적의 반복 승인 수. 기존 Mac 승인 대비 주간 순절약시간이 양수일 때만 “시간 절약”으로 판정한다.

### [P2] Memory Review는 기억 품질을 높이지만 사용자의 새 노동이 될 가능성이 높다

모든 기억 후보를 검토하게 하면 대화할수록 inbox가 늘어난다. 잘못된 후보를 판별하는 데 원대화까지 다시 읽어야 할 수 있다.

**권장 제한**

- 사용자가 “기억해”라고 명시한 항목과 이후 행동을 바꾸는 고영향 후보만 검토 큐에 넣는다.
- 하루 후보 상한과 자동 만료를 둔다.
- 한 번도 회수되지 않은 후보는 자동 폐기한다.
- 기억이 답변/계획을 실제로 바꿀 때만 사용자에게 이유를 표시한다.
- 핵심 지표는 기억 수가 아니라 잘못된 회수율, 재설명 횟수, 주간 검토시간이다.

### [P2] Capability Forge는 플레이북 유지보수 지옥으로 변할 수 있다

UI selector, API, 모델, 권한, 로컬 환경이 바뀔 때마다 플레이북이 깨질 수 있다. 자동 회귀시험 자체도 비용과 노이즈를 만든다.

**권장 제한:** 동일 작업이 월 3회 이상 반복되고, 수동 시간이 누적 30분 이상이며, 성공 증거가 기계적으로 검증 가능한 경우에만 플레이북으로 승격한다. 30일간 미사용 또는 연속 2회 실패 시 폐기 후보로 둔다.

### [P2] Attention Governor는 “알림 최적화” 자체가 새로운 튜닝 프로젝트가 될 수 있다

사용자의 상황·수면·업무시간을 과도하게 추론하면 또 다른 기억·센서·규칙 시스템이 필요해진다.

**권장 제한:** 초기에는 네 가지 고정 등급과 하루 한 번의 사용자 지정 시각만 사용한다. 행동 예측이나 감정 추론은 하지 않는다.

### [P2] 실시간 상태와 문서 상태가 섞일 수 있다

문서가 스스로 실시간 점검을 하지 않았다고 밝힌 점은 좋다. 하지만 build 9 존재, Telegram 제한, worker 흐름 같은 표현은 시간이 지나면 쉽게 낡는다.

**권장 수정:** 로컬 구현 주장마다 검증 시각, commit/hash, 테스트 명령과 결과, 운영/소스/설계 상태를 붙인다. 24시간이 지난 운영 상태는 UNKNOWN으로 자동 간주한다.

## 5. 사용자 시간 절약 검증

### 순시간 공식

각 기능은 아래 식으로 7~14일 동안 측정해야 한다.

**순절약시간 = 기존 수동시간 - (AI 검토시간 + 승인시간 + 오류수정시간 + 재실행시간 + 주간 유지보수시간)**

개발시간은 초기 투자로 별도 기록하되, 8주 예상 사용량으로 나눈 상각시간도 함께 본다.

### TOP 3별 냉정한 판정

| 기능 | 현재 판정 | 시간을 줄이는 조건 | 시간을 늘리는 실패 조건 | 14일 중단 기준 |
|---|---|---|---|---|
| Secure Action Inbox | **기반 기능, 미검증** | Mac 승인보다 카드가 짧고, 동일 목적 승인이 합리적으로 묶이며, 결과가 자동 돌아옴 | 긴 계획, 잦은 Face ID, 중복 승인, 앱 전환 실패 | 주간 순절약시간 ≤ 0 또는 승인 후 되돌림 > 5% |
| Exception-Only Briefing | **잠재 고효율, 고위험** | critical recall이 충분하고 정상 검토량을 실제로 줄임 | false negative, UNKNOWN을 정상 처리, 중복 사건 | critical 누락 1건 또는 오탐 검토시간이 기존 검토시간 이상 |
| Memory Review | **연속성/개인정보 기능, 시간 절약 근거 약함** | 재설명 감소가 검토시간보다 큼 | 후보 큐 증가, 낡은 기억 수정, 원문 재검토 | 후보 검토시간이 재설명 절약시간 이상 |

### 시간 절약 관점의 권장 재분류

**운영 기반:** Secure Action Inbox, Flight Recorder, 채널 권한 분리  
**실제 시간 절약 실험:** 이메일/문서 읽기 전용 초안, Evidence Ledger 누락 검사, 결정형 Home Assistant 반복작업  
**장기 연구:** Memory Review, Capability Forge 자동 승격, 영상 Evidence Twin

## 6. 가게 Evidence Twin 필수 개인정보·노무 체크리스트

아래 항목 중 하나라도 아니오/모름이면 실제 영상 분석을 시작하지 않는다.

- [ ] CCTV 설치 목적과 실제 촬영 범위가 문서화돼 있다.
- [ ] 공개 장소/직원 구역/고객 ROOM을 구분해 법적 근거를 검토했다.
- [ ] 촬영 사실, 목적, 관리책임자, 연락처를 적법한 방식으로 고지한다.
- [ ] AI 분석과 파생 사건 데이터의 목적·항목·보유기간·접근자를 정의했다.
- [ ] 기존 영상의 감사 목적 재사용이 허용되는지 검토했다.
- [ ] 보관기간 만료 시 원본·썸네일·OCR·임베딩·백업까지 삭제된다.
- [ ] 영상 조회·반출·내보내기·AI 처리의 접근 로그가 남는다.
- [ ] 외부 AI·클라우드·개발자에게 원본 영상이 전송되지 않는다.
- [ ] CCTV와 별도 마이크 모두 음성 녹음 기능을 사용하지 않는다.
- [ ] 직원 감시설비 관련 노사협의 절차 적용 여부를 검토했다.
- [ ] 직원과 고객의 열람·정정·이의제기 요청 처리 절차가 있다.
- [ ] AI 결과가 급여·징계·해고·신고의 단독 근거가 되지 않는다.
- [ ] 사건 검토자는 원본과 반대 증거를 함께 볼 수 있다.
- [ ] 실명 매핑은 최소 인원만 접근하고 일반 분석 데이터와 분리된다.
- [ ] 카메라/NVR/장부의 시계 오차를 매일 기록한다.
- [ ] 허위 양성으로 특정 직원을 반복 표적화하는지 정기 점검한다.

## 7. 원문에 바로 반영할 수정 우선순위

### 즉시 수정

1. 법률/노무 출시 게이트와 음성 녹음 금지를 추가한다.
2. 외부 검증 사실을 출처 유형별 라벨로 바꾼다.
3. Signals의 “신뢰가 쌓여” 인과 문구를 관찰 문구로 낮춘다.
4. Home Assistant 200만을 2025년 발표 시점의 역사적 수치로 고친다.
5. GitHub 별 수를 본문에서 제거하거나 재현 가능한 부록으로 이동한다.
6. TOP 3를 운영 기반과 시간 절약 실험으로 분리한다.
7. Exception Briefing의 14일 shadow와 critical 누락 1건 중단 기준을 넣는다.

### 구현 전 수정

1. 후보별 재사용 구성요소와 효과 근거를 분리한다.
2. 소수점 점수를 등급으로 바꾸거나 전체 산식을 공개한다.
3. OCR 전에 7일 표준 장부 수기 검증 단계를 추가한다.
4. 모든 시간 절약 주장에 순시간 공식을 적용한다.
5. 기억 후보의 일일 상한·만료·미사용 폐기 규칙을 추가한다.

## 8. 최종 Red-Team 결론

보고서의 가장 가치 있는 생각은 Capability Forge → Evidence Twin → Attention Governor의 폐루프다. 그러나 그것이 사용자의 시간을 줄이는 것은 자동으로 성립하지 않는다.

- Forge는 유지보수할 플레이북을 늘릴 수 있다.
- Evidence Twin은 오탐 검토와 개인정보 책임을 늘릴 수 있다.
- Attention Governor는 중요한 사건을 숨길 수 있다.
- Memory Review는 사용자의 새 inbox가 될 수 있다.
- Secure Action Inbox는 승인 위치만 바꾸고 승인량은 그대로 둘 수 있다.

따라서 성공 기준은 기능 수, 모델 크기, GitHub 관심도, 기억 수가 아니다.

1. **순수하게 줄어든 사용자 시간**
2. **중요 사건 누락 0건**
3. **오탐 때문에 낭비한 시간**
4. **법적·개인정보 절차를 통과한 데이터만 사용했는지**
5. **같은 실패가 회귀시험 뒤 다시 발생했는지**

이 다섯 가지를 14일 shadow 실험으로 측정하기 전에는 “최적 TOP 3”가 아니라 “검증할 TOP 3 가설”로만 표현해야 한다.
